# greminder 仕様書

更新日: 2026-09-14 / 対象: 現在の初期実装（0.1.0）

この文書は実装済みの動作を記述する。将来の構想は「未実装・検証範囲」に分ける。

## 1. 目的と対象環境

Google TasksをデータソースにするiOS / macOSネイティブのタスク管理アプリ。SwiftUIの一覧内入力と、端末内AIによる操作提案を提供する。Appleリマインダーの操作を参照するが、Appleリマインダーのデータを読み取る機能は持たない。

| 項目 | 仕様 |
|---|---|
| OS | iOS 26以上、macOS 26以上 |
| UI | SwiftUI、システムのライト／ダーク表示に追従、日本語・英語 |
| 開発環境 | Xcode 26.3 / Swift 6.2.4で確認 |
| 状態管理 | The Composable Architecture（TCA） |
| Google API | Google API Objective-C Client for RESTのTasksサービス |
| AI | Apple Foundation Modelsの端末内モデル |
| 音声入力 | WhisperKit 1.1.0、端末内で文字起こし |
| 通知 | UserNotificationsによる端末通知、予定日差分の確認 |
| 初回起動 | OAuth設定不要のサンプルモード |

## 2. 画面構成

選択済みの[デザイン案2](design/selected-concept.png)を基に、下部のAI入力と、その直上に表示する提案プレビューを採用する。Macはサイドバーとタスク一覧、iPhoneはリスト画面と一覧画面をネイティブナビゲーションで切り替える。Macのメイン画面は1ウインドウとし、アカウント・保存待ち操作を同じ状態で管理する。

### リスト画面／サイドバー

- 「今日」: 今日以前の予定日を持つ未完了タスク。期限超過を含む。
- 「予定あり」: 予定日を持つ未完了タスク。
- 「すべて」: 未完了タスク。
- 「完了」: 完了済みタスク。
- Google Tasksの各リスト: そのリストの未完了タスク。
- サンプル／接続状態、保存中／未保存状態、設定、新規リスト作成。

スマートリストのカード件数と一覧は同じ抽出規則を使う。対象の親に付随する未完了サブタスクも含め、日付のない子がある場合もカードと見出しの件数を一致させる。サブタスクは1階層で、親の開閉ボタンから折りたためる。

### 新しいリスト

リスト名と、12種類のアイコン・12色の背景色を選択する。プレビューは選択を即座に反映する。色はチェックマーク、アイコンは枠で選択状態を示し、VoiceOverにも選択状態と名称を伝える。初期値はリストアイコンと青。作成中は編集・二重送信・閉じる操作を無効にし、成功後は新しいリストへ移動する。失敗時は名前と外観を保持し、再試行できる。

名前はGoogle Tasksのリストとして保存する。アイコン・背景色はAPIに項目がないため、端末内でアカウントとリストIDに紐づけて保存し、再取得時に適用する。他の端末やGoogle公式アプリへ外観を同期する機能はない。

### 表示言語

設定 → 表示 → 表示言語から「システム設定に従う」「日本語」「English」を選ぶ。初期値はシステム設定。選択は端末に保存し、その場で画面のラベル・操作・アクセシビリティ・日付表示へ反映する。音声認識言語は独立した設定であり、表示言語変更では変えない。入力済みのタスク・メモ・リスト名も書き換えない。新規生成するサンプルとAIの入力例は選択言語を使う。

マイク許可の説明はInfoPlist.stringsで日本語・英語を提供する。OSが表示する権限ダイアログ自体の言語はOSのアプリ言語設定に従う。

### タスク一覧

一覧名・件数・日付またはデータソースを表示し、各行に完了ボタン、タイトル、メモ、リスト名、必要に応じて予定日を表示する。予定日のある画面では期限超過を赤で示す。

新規入力は右下の丸い＋FABから行い、ツールバーから再読み込み、設定へアクセスする。完了済みの確認と未完了への復帰は「完了」リストで行う。

検索はホーム（リスト一覧）のみで行う。ホームの検索アイコン／⌘Fで画面下部の検索欄を表示・非表示にする。入力中は設定欄を隠し、検索欄をキーボードの直上に置く。全リストのタイトルとメモを対象に検索し、完了済み・サブタスクも含める。結果には所属リストを表示し、タップでそのリストとタスク詳細を開く。検索語は通常のタスク一覧を絞り込まない。検索欄を閉じると検索語を消去する。macOSではホームに相当するサイドバーに検索を配置する。

検索欄内の丸い×は検索語をクリアする。検索欄の横の×はフォーカスを解除してキーボードのみ閉じ、検索語と結果を保持する。どちらの操作もホームの検索欄自体は表示したままにする。

ツールバーのAIアイコンで「AIに頼む」入力欄を表示・非表示に切り替える。表示中は輝きアイコンと丸い背景、非表示中は斜線付きの輝きアイコンを使い、色に頼らず状態を示す。初期状態は表示。非表示にすると一覧が広がり、AI入力のキーボードを閉じる。入力済みの指示とAIの提案は保持する。表示状態は同じウインドウ内で保持し、アプリ再起動後は初期状態に戻る。

リスト画面にも右下に追加FABを表示する。タスク画面のFAB・見出し・件数・操作アイコン・AI入力のアクセントは選択リストの背景色に揃える。スマートリストは固有の色を維持する。FABは56 ptの円形ボタンで、リストでは設定欄、タスクではAI入力欄の上に配置する。

iOSの詳細モーダルはタイトル・項目名・操作ラベルを標準文字色（ライト時は黒、ダーク時は白）で表示する。補足・セクション見出しはグレー、削除・エラーは赤を使う。確定ボタン・トグル・操作アイコンには所属リストの色を使う。

## 3. 入力仕様

| 操作 | 結果 |
|---|---|
| Macの余白ダブルクリック | 一覧内に新規入力行を開いてフォーカス |
| iOSの余白タップ | 同上 |
| ＋／Macの⌘N | 同上 |
| タイトル入力後のEnter／次へ | 保存を開始し、直下の新規行へフォーカス |
| 空タイトルでEnter／次へ | 空タスクを作らず入力を終了 |
| 既存タイトルを選択 | タイトル・メモ・予定日を一覧内で編集 |
| 既存タイトル編集後のEnter | 変更を保存し、その直下に新規行 |
| 編集欄の「完了」／メモ欄のEnter | 保存して入力を終了 |
| Macの余白クリック | 編集を確定して入力を終了 |
| MacのEsc | 未確定の編集を破棄して入力を終了 |
| 別のタスク／リストへ移る | 現在の有効な編集を確定して移動 |
| 行のコンテキストメニュー | 編集、直下へ追加、サブタスク追加、削除 |

タイトルは前後の空白を除去し、最大1,024文字、メモは最大8,192文字。上限を超えた入力はエラーを表示して保持する。空の既存タイトルを確定した場合は元のタスクを削除しない。

新規入力のリストは選択中のリスト、スマートリストでは「仕事」または先頭リストを使う。「今日」から作るタスクには今日の日付を設定する。それ以外は日付なしで開始する。直下への追加は、同じリスト・同じ親の位置関係をSDKの`previous` / `parent`に渡す。

保存中も次の行を入力できる。失敗すると入力済みの行と送信待ちの変更を画面に残し、「再試行」で再開する。保存待ち状態ではアカウント切り替えを無効にする。

削除には確認ダイアログを表示し、子も削除対象になる。アプリ独自のゴミ箱・Undoは実装していない。

### タスクの詳細

一覧のⓘから詳細を開く。Macでは一覧右側のパネル、iOSではモーダルとして表示する。iOSは左上に×、右上に所属リスト色の✓を配置し、タイトルとメモ、日付と通知、整理をグループ化する。タイトル・メモ・予定日・完了状態・端末通知・サブタスクをまとめて扱う。リスト名は読み取り表示。詳細を開いたまま別の行を選ぶと、有効な変更を保存して切り替える。

入力欄からのフォーカス移動、タイトルのsubmit、日付・完了の変更、詳細の「完了」／閉じる（iOSは×・✓・下スワイプ）で保存する。iOSの×も有効な変更を保存して閉じる。無効な入力は閉じずに保持し、保存失敗では再試行できる。インライン編集と保存キューを共用するため、同じタスクを二重のドラフトで編集しない。[観察と実装の詳細](detail-behavior.md)

## 4. 端末内AI

WhisperKitを除くLLM処理は`Packages/LocalLLM`へ分離する。アプリはクライアントへモデル名とプロンプトを渡し、async/awaitで結果を受け取る。現在の対応モデルは`apple.foundation-models`。未知のモデル名はエラーとして扱う。モデルの初期化・セッション・SDK固有の分岐はパッケージ側で管理する。公開APIと追加手順は[LocalLLM](../Packages/LocalLLM/README.md)を参照。

1. 下部に自然文を入力する。
2. 内部LocalLLMパッケージが指定モデルを選び、タスクデータと指示から構造化された提案を非同期生成する。
3. タイトル・対象リスト・予定日・子タスクを一覧下部で確認する。
4. 「N件を追加／変更」で通常入力と同じ保存処理へ送る。キャンセルで取り消せる。

対応操作は追加、予定日変更、完了。AIによる削除、任意コード実行、外部URL呼び出しは提供しない。提案作成後にタスクデータや接続アカウントが変わった場合は適用を拒否し、再生成を促す。適用時には入力中の編集も先に検証・確定するため、未確定の変更をAIで上書きしない。キャンセル済みのリクエストの結果は、別の生成中であっても採用しない。

| 制限 | 値 |
|---|---|
| 指示 | 1,500文字以内 |
| AIへ渡すタスク | 80件以内。リスト選択中はそのリストに限定 |
| 操作数 | 1〜10操作 |
| 子タスク | 追加操作あたり10件以内、1階層 |
| 対象 | 与えられたリストID・タスクIDに一致するもの |
| 日付 | 有効な`yyyy-MM-dd` |

端末・Apple Intelligence設定・モデル準備状況・日本語対応状況に応じて利用可否と理由を表示する。「入力例を試す」はモデルを呼ばず、親1件と子2件の固定提案を表示し、「AI未使用」と明示する。

指示の解釈は端末内で行う。Google接続中に確定したタスクはGoogleへ送信する。アプリから外部の生成AIサービスへ指示やタスクを送る実装はない。

## 5. データとGoogle接続

| モード | 読み書き先 | 永続化 |
|---|---|---|
| サンプル | SDKの`service.testBlock`で処理 | Application Support内のJSON |
| `--design-preview` | 同じ`testBlock` | メモリのみ、再起動で初期化 |
| Google接続 | SDK + Google Sign-Inの認証情報 | Google Tasks。ライブキャッシュなし |

初期サンプルは「仕事」「プライベート」「買い物」の3リスト、10タスク（未完了7、完了3）。日付はサンプル作成日から設定する。通常起動で保存したサンプルは、再起動時も保存内容を復元する。

Google接続にはターゲットごとのOAuthクライアントID、URLスキーム、署名設定が必要。[google-setup.md](google-setup.md)を参照する。1アカウントを扱い、以前のサインインを復元する。サンプルをGoogleに自動転送しない。サインアウトするとサンプルへ戻る。接続先の読み込みが成功するまで現在のデータと保存先を維持し、接続・切断の失敗時に表示と保存先が食い違わないようにする。

取得時は全リストと各リストのタスクをページングする。完了・非表示済みタスクも取得対象にする。初回読込、操作中でない場合のフォアグラウンド復帰、明示的な再読み込みを提供し、外部での変更を常時監視する同期は行わない。

Googleの`due`は日付として扱う。時刻、場所、タグ、繰り返しなどをGoogle APIへ同期できる項目として表示しない。

## 6. 音声入力

一覧ツールバーとAI入力欄のマイクから音声入力を開く。モデル準備 → 録音開始 → 停止して文字起こし → 結果を編集 → 入力欄へ反映、の順に操作する。録音は最大60秒で自動停止する。反映だけではタスク保存やAI実行を開始しない。

設定の「音声入力」で認識言語とモデルを選ぶ。変更は端末に保存され、次に開いた音声入力から使用する。初期値は日本語 / Base。

| 設定 | 選択肢 |
|---|---|
| 認識言語 | 自動判定、日本語、英語、中国語、韓国語、フランス語、ドイツ語、スペイン語、イタリア語、ポルトガル語 |
| 音声モデル | Tiny（軽量）、Base（標準）、Small（精度優先）、Large v3 Turbo（圧縮版、約626 MB） |

すべて多言語モデルを使用する。Large v3 Turboは[WhisperKit公式の対応表](https://github.com/argmaxinc/argmax-oss-swift#model-selection)にあるiOS / macOS共通の圧縮版`openai_whisper-large-v3-v20240930_626MB`を選択する。言語の固定はWhisperのデコード言語指定、自動判定は`detectLanguage = true`で行い、翻訳はしない。設定画面でモデルを変更した時にモデルとトークナイザーを取得・読み込みし、Application Supportへキャッシュする。取得済みのデータは再利用する。処理中は共通ローディングUIを表示し、成功後に選択設定を保存する。失敗時は元の選択を維持し、再度選択して再試行できる。初期モデルなど未準備のモデルは音声入力画面からも準備できる。準備済みのモデルはオフラインで利用できる。大きいモデルほどメモリ・ディスク容量を要し、速度と精度はデバイスや音声に依存する。

準備開始、モデル取得後の読み込み前、録音開始前、文字起こし前にモデル保存先ボリュームの空き容量を確認する。Large v3 TurboはSimulatorで8 GB、実機・ネイティブMacで2 GBを実行許可の下限とする。これらは作業領域を残すための保守的な設定で、必要量の実測値や動作保証値ではない。モデル本体の約626 MBに加え、Core MLのコンパイルキャッシュが増える。容量不足または容量取得不能では、モデル処理を開始せず理由と再試行方法を表示する。[Simulatorクラッシュ調査](diagnostics/large-v3-turbo-simulator.md)を参照。

マイクは録音開始時にOSの許可を求める。文字起こし中は録音を停止し、音声を外部へ送信しない。録音ファイルは処理完了・失敗・キャンセル時に削除する。バックグラウンドへ移ると音声入力をキャンセルする。無音、短すぎる録音、ダウンロード失敗、マイク拒否は画面に理由を表示する。誤認識に備えて結果の確認・編集を必須の操作としている。

## 7. 通知と予定日の確認

iOSの詳細モーダルはリマインダーを参考に、「日付」「時刻」のアイコン・設定値・スイッチを同じカード内に配置する。行をタップすると日付はカレンダー、時刻はホイールをインラインで展開し、もう一度タップすると閉じる。一度に開くピッカーは1つ。操作時はタイトル・メモのキーボードを閉じる。

「時刻」オフはそのタスクの端末通知だけを停止し、予定日と保存済み時刻を維持する。オンへ戻すと保存済み時刻を再利用する。日付がない状態で時刻をオンにすると今日を予定日にする。日付をオフにすると予定日と通知を解除する。日付を明示変更した場合は端末の通知日も合わせ、時・分と個別のON/OFFは維持する。日付・時刻・ON/OFFはタスクの編集内容と一緒に検証し、タイトルなどが無効な間は通知だけを保存しない。外部取得での日時差分は従来どおり確認する。

端末全体の通知が無効の場合は時刻操作を無効にし、「通知を設定…」から設定画面へ進める。時間帯は端末の現在の設定を読み取り表示する。API上の制限説明はカード外の補足へまとめる。繰り返しや個別の時間帯変更は追加しない。

設定からこの端末の通知を許可し、新しく読み込むタスクの標準時刻を指定できる（初期値09:00）。既に時刻があるタスクへ標準時刻の変更を一括適用しない。予定日のある既存タスクの編集欄には「端末の通知」を表示し、個別に日時を変更できる。完了、削除、予定日解除、通知オフでは保留通知を取り消す。

**Google Tasksの通知時刻・通知設定との双方向同期は提供できない。** [公式Tasksリソース](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks)の`due`は日付のみで、時刻情報は破棄される。通知時刻を取得・変更する公開APIはない。タスクの予定日の編集はGoogleへ送信するが、端末の通知日時の編集はGoogle側の通知設定を変えない。

取得成功時、端末の通知日がTasksの予定日と異なり、かつ端末の通知日時が過ぎているタスクをダイアログに一覧表示する。「はい、端末の日付を更新」でTasksの予定日を端末へ反映し、端末の時・分は保持する。「いいえ、変更しない」では既存日時を保持し、同じ起動中は同じ差分を再確認しない。次回起動は再確認する。**時刻同士の比較ではなく、取得できる予定日との差分確認である。** まだ過ぎていない通知について、取得した予定日が変わった場合は時・分を保持して通知日を更新する。

通知設定は端末ローカル。アカウントとサンプルを分けて記録し、現在のアカウントの直近60件をOSへ予約する。残りは次の起動・更新で補充する。アプリが停止している間のGoogle変更を取得しないため、長期間起動しない場合は通知が古くなったり、60件以降が予約されなかったりする。過去の時刻を即時通知として再送しない。集中モードやOS設定によって表示・音が抑制されることがある。

## 8. 確認済みの動作

- macOSの純正リマインダーを操作し、余白、Enter連続入力、空行終了、既存行編集を観察。[記録](input-behavior.md)
- greminderのMac実行で、日本語の貼り付け→Enter→次行への継続入力、空行終了、完了、再起動後の保存を確認。
- iPhone 17 Pro Max / iOS 26.2 Simulatorで、余白からの入力、Enter後の新規行、かな入力の変換確定と保存の分離、次行への継続入力、画面遷移を確認。
- Macで実際のFoundation Modelsを使い、翌日・仕事リストへの追加提案を生成し、サンプルAPIへ適用。
